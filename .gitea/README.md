# Gitea Workflows

These workflows run only on Gitea and **are not synced** to GitHub.

## Sync to GitHub (`workflows/sync-to-github.yaml`)

Syncs the repository to GitHub on every **push to the `main`** branch or **version tag**:

- Pushes the `main` branch to GitHub (excluding the `.gitea` and `internal/` folders).
- Pushes version tags (`vX.Y.Z` or `vX.Y.Z-suffix`, e.g. `v1.0.0`) to GitHub.
- On a version tag, creates the **release on Gitea and on GitHub** (tags with a suffix, e.g. `-beta`, are marked as pre-release).

### Release notes

The release notes are generated by `scripts/release-notes.sh` from:

- the version's section in `CHANGELOG.md`
- the version's row in the "Version History" table of `VERSIONS.md` (Alpine, btop++, ttyd)

Preview them locally (from the repository root):

```bash
.gitea/scripts/release-notes.sh 1.0.0
```

The Gitea release uses the automatic Actions token; the GitHub release uses `SYNC_GITHUB_TOKEN` (`Contents: Read and write` is enough). If a release already exists for the tag, it is left unchanged.

### Gitea configuration

In the repository **Settings → Secrets and Variables**:

| Type       | Name                 | Description |
|------------|----------------------|-------------|
| **Secret** | `SYNC_GITHUB_TOKEN`  | GitHub Personal Access Token (fine-grained: `Contents: Read and write`; classic: `repo` scope). |
| **Variable** | `SYNC_GITHUB_REPO`     | GitHub repository in the form `owner/repo-name` (e.g. `hbixu/btop-plus-plus`). |

Note: Gitea does not allow secret/variable names starting with `GITEA_` or `GITHUB_`.

### GitHub token notes

- **Permissions**
  - **Classic PAT:** scope `repo` (or `public_repo` if the GitHub repo is public).
  - **Fine-grained PAT (recommended):** Repository access = this repository only; **Contents** = Read and write. You can add other repositories to the same token later if needed.

- **Expiration**
  - Not required for classic PATs (you can choose "No expiration"), but setting an expiration (e.g. 1 year) is recommended. Fine-grained PATs must have an expiration (max 1 year).
  - Before the token expires: create a new token on GitHub, update the `SYNC_GITHUB_TOKEN` secret in Gitea, then revoke the old token on GitHub.
